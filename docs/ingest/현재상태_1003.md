# 자료 넣기 파이프라인 현재 상태 (2026-10-03, origin/main cd41323 기준)

「내 SNS 주소만 넣으면 나처럼 말하는 AI」의 흐름을 코드 끝까지 읽고 정리했다. 고치기 전 상태다.

## 1. 전체 흐름

| 단계 | 파일 | 하는 일 |
|---|---|---|
| ① 주소 넣기 | `src/components/home/HomeMake.tsx` | 주소를 칩으로 받아 브라우저에 보관(`saveHomeDraft`) → 로그인 → `/os` |
| ② 초안 시작 | `src/components/os/OsShell.tsx` → `NewBotSheet.tsx` `LinkDraftTab` | 보관분을 읽어 바로 `POST /api/os/twin-draft` |
| ③ 읽기 | `src/app/api/os/twin-draft/route.ts` → `domains/os/twin-draft.ts` `collectDraftSources` | 링크 3개까지 동시에 읽기. 마감 50초 |
| ④ 초안 쓰기 | `twin-draft.ts` `makeTwinDraft` → `askSideText`(솔라 미니 먼저, 막히면 Gemini 라이트) | 모델 1번. 자료 한 편 1,500자, 합계 9,000자만 보여 준다 |
| ⑤ 주인이 고침 → 만들기 | `api/os/twin-draft/create/route.ts` | 봇 생성, 인사말 = 「무엇을 배웠나」 한 줄 + 모델 인사말 |
| ⑥ 자료 저장 | `create` 의 `after()` → `domains/os/knowledge.ts` `addDraftSources` | 링크를 **다시** 읽어 `addKnowledgeSource` 로 저장 |
| ⑦ 조각·임베딩 | `domains/knowledge/actions.ts` + `embedding.ts` | 500자 조각, 조각마다 Gemini 임베딩(768차원)을 **하나씩 차례로** |
| ⑧ 답할 때 찾기 | `app/api/chat/route.ts` → `queries.ts` `matchKnowledge` | 벡터 + 낱말 하이브리드, 고쳐 찾기(corrective), 울타리(fence) |

## 2. 소스별 지도

| 소스 | 초안 때 읽는 것 (③) | 봇 자료로 저장되는 것 (⑥) | 실패하면 |
|---|---|---|---|
| 네이버 블로그 (`blog.naver.com/아이디`) | 공개 RSS 최근 3편, 편마다 본문(PostView, 막히면 모바일) + 날짜 | ❌ 편마다가 아니라 **블로그 첫 화면** 을 `readUrl` 로 한 번 읽음 (잘 되면 RSS 목록 요약 한 장, 본문 전문 아님) | 「글 붙여넣기」 안내 |
| 네이버 블로그 글 하나 (`/아이디/글번호`) | ❌ 글 번호를 버리고 그 블로그 최근 3편을 읽음 | 그 글 하나 (본문 + 제목 + 작성일 머리) | 같음 |
| 티스토리 | 공식 RSS 최근 3편 | ❌ 첫 화면 한 장 | 사람 말 이유 |
| 브런치, 일반 웹 글 | 글 하나 본문(readability), 날짜·출처 머리 | 같은 글 | 사람 말 이유 |
| 유튜브 채널 (`@핸들`) | 최근 영상 3개, 영상마다 자막(시각 [분:초] 포함) 없으면 설명 | ❌ 채널 화면을 일반 웹으로 한 번 읽음 → 영상 자막은 안 들어감 | 사람 말 이유 |
| 유튜브 영상 하나 | 자막 우선 → 막히면 Gemini 영상 정리(하루 한도) → 설명·챕터 | 같은 것 (다시 읽음, 정리는 DB에 남아 재사용) | 「자막 없어 제목·설명만」을 글에 적음 |
| 인스타그램 | 공개 계정 게시물 캡션 5개 | ❌ **저장 안 함** (`draftLinkKind` 가 paste 라서 건너뜀) | 「글을 붙여넣어 주세요」 |
| 스레드 | 공개 프로필 소개 + 글 5개 | ❌ **저장 안 함** | 같음 |
| X, 틱톡 | 안 읽음 | 안 읽음 | 「링크만 저장돼요」 |
| 큰 장터 상품(스마트스토어, 쿠팡) | 안 읽음 | 안 읽음 | 「상품 설명을 붙여 넣어 주세요」 |
| 파일 PDF·DOCX·PPTX·HWP·XLSX·CSV·TXT·VTT | 홈에서는 안내만 | `/api/creator/knowledge/process` (업스테이지 문서 파싱, 쪽 수 한도) | 실패 이유 코드 |
| 붙여넣은 글 | 그대로 | 그대로 (`addTextSource`) | 30자 미만은 뺌 |

## 3. 저장·조각

| 항목 | 지금 | 빈 곳 |
|---|---|---|
| 원문 보관 | `knowledge_sources.content` 에 전문(최대 10만 자), `title`, `original_url`, `source_type` | 글 해시·글자 수·글 날짜 칸이 없다. 링크 자료는 `fetched_at` 도 안 적는다 |
| 중복 | 자동 가져오기(feeds)만 주소로 거름 | 같은 글을 두 번 넣으면 **두 번 저장**, 조각·임베딩도 두 번 |
| 조각 크기 | 문단 → 줄 → 문장 순으로 잘라 최대 500자 | **겹침 없음** → 경계에 걸린 사실이 반쪽으로 갈림 |
| 조각 메타 | `chunk_index` 하나 | 출처 주소·날짜·위치(몇 번째/전체)·소제목·영상 시각이 조각에 없음. 소제목은 임베딩 머리말에만 |
| 인스타 묶음 | 게시물 사이 `---` 줄 | `---` 가 따로 조각에 섞임 |
| 임베딩 속도 | 조각마다 하나씩 차례로 (`for … await`) | 10만 자 = 조각 약 200개 = 길게는 1분 넘음 |

## 4. 페르소나(봇 설명)

| 항목 | 지금 | 빈 곳 |
|---|---|---|
| 재료 | 자료마다 **앞 1,500자**, 합계 9,000자 | 숫자·사례가 글 뒤쪽에 있으면 못 봄 |
| 뽑는 칸 | 이름, 한 줄 소개, 인사말, 대상, 주제, 말투 규칙, 금지선, 첫 질문, 예시 1쌍 | 「구체적 사실」「고유 표현」 칸이 없다 → 봇 설명에 리더만의 숫자·경험이 안 들어감 |
| 인사말 | 「○○님 블로그에서 말투와 주제를 배웠어요」 + 모델 인사 | 리더 자료의 구체적 사실을 인용한다는 보장이 없음 |
| 자료 이해 카드 | `understand.ts` 가 자료 하나씩 주제·말투·사실을 뽑는다(주인이 눌러야) | 초안 흐름에서는 안 씀 |

## 5. 검색(답할 때)

있는 것: 봇별 격리(mentorId 필수), 벡터+낱말 하이브리드, Q&A 가산점, 고쳐 찾기, 자료 울타리(지시 무시), 「자료에 없으면 없다고 먼저 말한다」 규칙. → 이번에 손대지 않는다.

## 6. 시간 (60초 첫마디 목표)

| 구간 | 지금 |
|---|---|
| 링크 읽기 | 마감 50초 (유튜브 영상 정리는 최대 40초 기다림) |
| 초안 모델 | 솔라 20초 한도 |
| 합계 최악 | 약 70초 → 목표 60초 넘음 |
| 자료 저장 | 만든 뒤 뒤에서(`after`). 처리 상태값(pending/processing/completed/failed)과 조각 수가 이미 있음 |

## 7. 이번에 고칠 것 (효과 큰 순)

1. 봇 자료 = 초안이 읽은 것과 같게: 블로그·티스토리·유튜브 채널은 최근 글/영상을 편마다, 인스타·스레드도 저장. 블로그 글 주소는 그 글.
2. 원문 보관 칸(해시·글자 수·글 날짜·가져온 시각) + 같은 글 두 번 저장 막기.
3. 조각: 겹침, `---` 정리, 조각마다 메타(출처·제목·위치·날짜·소제목·영상 시각).
4. 페르소나: 자료 뒤쪽의 숫자·사례 문장까지 골라 보여 주고, 「사실」「고유 표현」을 뽑아 봇 설명에 넣고, 인사말과 예시 2쌍이 사실을 인용하게.
5. 속도: 읽기 마감 50→35초, 임베딩 동시 4개.
