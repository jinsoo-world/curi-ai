# 토스 라이브 열쇠 교체 절차 (승인 메일이 오면 대표가 하는 5걸음)

작성 2026-09-23. 상태 = 토스페이먼츠 MID(크레딧 충전 방식) 심사 중, 곧 승인 예정.
지금 라이브(www.curi-ai.com)의 결제 화면에는 **테스트 열쇠(test_ck_)** 가 박혀 있어 진짜 돈은 움직이지 않는다.
승인 메일이 오면 아래 5걸음으로 라이브 열쇠로 바꾼다. 소요 약 20분. **열쇠 값은 이 문서·슬랙·코드 어디에도 적지 않는다.**

## 0. 미리 알아둘 것

| 항목 | 값 |
|---|---|
| 배포 | Vercel, 대표 개인 계정 `jin-7378`, 프로젝트 `app`. main 에 푸시하면 자동 배포 |
| 열쇠 자리 | Vercel 환경변수 2개 = `NEXT_PUBLIC_TOSS_CLIENT_KEY`(화면용, 공개됨) · `TOSS_SECRET_KEY`(서버용, 비밀) |
| 결제 화면 | `/charge`(옛 화면) · `/os/charge`(봇 팀 다크 화면). 결제 속은 같은 함수 하나(`src/domains/credit/charge-client.ts`) |
| 승인 창구 | `POST /api/credits/charge` = 토스에 직접 확인(confirm) 받고 클로버를 넣는다. **클로버는 이 confirm 이 준다** |
| 웹훅 | `POST /api/billing/webhook` = 결제 상태만 바꾼다(0915 결정). 웹훅이 클로버를 주지 않는다 |
| 점검 도구 | `node scripts/toss-live-check.mjs` → 라이브 화면에 어느 열쇠가 박혔는지 읽는다 |
| 상품 | `src/domains/credit/packs.ts` 표 하나. 화면·서버가 같은 표를 읽는다 |

토스 개발자센터에서 열쇠를 볼 때 = **새로 생긴 큐리AI 상점(MID)** 의 「라이브 키」 탭. 본체 큐리어스 상점(bill_curiomb62 · cp_curiou99ca)의 열쇠와 섞이지 않게 상점 이름을 먼저 확인한다.

## 1걸음. Vercel 환경변수 2개 교체 (5분)

1. Vercel → 프로젝트 `app` → Settings → Environment Variables
2. `NEXT_PUBLIC_TOSS_CLIENT_KEY` = 토스 개발자센터 「라이브 클라이언트 키」(`live_ck_` 로 시작) 로 바꾼다. 환경은 **Production 만**. Preview 는 테스트 열쇠 그대로 둔다
3. `TOSS_SECRET_KEY` = 「라이브 시크릿 키」(`live_sk_` 로 시작) 로 바꾼다. **Sensitive 체크**. Production 만
4. 저장 뒤 화면에서 두 값의 앞 글자가 `live_` 인지 눈으로 한 번 확인

⛔ Preview 까지 라이브로 바꾸면 미리보기 배포에서 실결제가 일어난다.

## 2걸음. 재배포 (5분)

환경변수는 **다시 배포해야** 화면에 박힌다(`NEXT_PUBLIC_` 값은 빌드 때 굳는다).

1. Vercel → Deployments → 가장 위 Production 배포 → 「Redeploy」. 「Use existing Build Cache」는 **끈다**
2. 배포가 Ready 가 되면 터미널에서 확인:
   ```bash
   node scripts/toss-live-check.mjs --expect live
   ```
   `/charge` `/os/charge` 둘 다 「라이브 live_ck_****xxxx」 로 나오고 마지막 줄이 「라이브 열쇠. 실결제가 일어난다」 여야 한다. 종료코드 0.
   테스트 열쇠가 남아 있으면 종료코드 1 = 1걸음 환경(Production) 을 다시 본다.

## 3걸음. 가장 작은 상품으로 실결제 1건 (5분)

⛔ 1,000원 같은 임의 금액으로 시험하지 않는다. 서버가 상품 표에 없는 금액을 거절하도록 되어 있다.
   시험은 **상품 표의 가장 작은 묶음**(지금 표 = 클로버 200개 9,900원) 으로 한다.

1. 대표 계정으로 로그인 → https://www.curi-ai.com/os/charge 열기
2. 결제 전 「지금 가진 클로버」 숫자를 적어 둔다
3. 가장 작은 묶음 → 「9,900원 결제하기」 → 법인카드로 결제
4. 확인할 것 3개
   - 결제 뒤 「충전 완료」 화면에 **클로버 200개가 들어왔어요** 와 새 잔량이 뜬다
   - 「봇 팀으로 돌아가기」 를 누르면 원래 있던 봇 대화(또는 /os) 로 돌아온다
   - 토스 개발자센터 → 결제 내역에 주문번호 `clover_p10_…` 이 DONE 으로 있다
5. Supabase → `credit_transactions` 에 `type = purchase`, `description = 그 주문번호` 인 줄이 **딱 1개** 다. 2개면 중복 지급 = 즉시 알린다

## 4걸음. 웹훅 도착 확인 (2분)

웹훅은 상태만 바꾼다(0915 결정). 클로버는 3걸음의 confirm 이 이미 줬으니 웹훅이 늦어도 고객은 이미 받았다.

1. 토스 개발자센터 → 웹훅 → 등록 주소가 `https://www.curi-ai.com/api/billing/webhook` 인지, **라이브 상점에도** 등록되어 있는지 본다(테스트·라이브가 따로다)
2. 3걸음 결제 건의 웹훅 발송 기록이 「성공(200)」 인지 본다
3. 실패(4xx/5xx) 면 Vercel → Logs 에서 `/api/billing/webhook` 줄을 본다. 재전송 단추로 다시 보낼 수 있다

## 5걸음. 환불 1건 시험 (3분)

1. 토스 개발자센터 → 3걸음 결제 건 → 「결제 취소」 → 전액 취소
2. 확인할 것 = 카드 승인이 취소로 바뀐다(카드사 문자 또는 토스 화면). 대표 계정 클로버는 **자동으로 빠지지 않는다** → Supabase 에서 `users.clovers` 를 200 개 되돌리고 `credit_transactions` 에 `type = refund` 한 줄을 남긴다(관리자 화면 `/admin/users` 의 클로버 칸에 음수로 넣어도 된다)
3. 환불규정 화면 https://www.curi-ai.com/refund 가 여전히 200 인지 (점검 도구가 같이 봐 준다)

여기까지 다 되면 결정로그에 한 줄:
`날짜 | 큐리AI 토스 라이브 열쇠 교체 완료·실결제 1건·환불 1건 시험 통과 | 승인 메일 도착 | 첫 고객 결제 뒤 정산 입금 확인`

## 되돌리기 (문제가 생기면 5분)

라이브 열쇠로 바꾼 뒤 결제가 이상하면 **테스트 열쇠로 되돌린다**. 되돌리면 그 순간부터 진짜 돈은 안 움직인다.

1. Vercel → Environment Variables → `NEXT_PUBLIC_TOSS_CLIENT_KEY` `TOSS_SECRET_KEY` 두 개를 토스 개발자센터 「테스트 키」(`test_ck_` / `test_sk_`) 로 다시 넣는다(Production)
2. Redeploy(캐시 끄기) → `node scripts/toss-live-check.mjs --expect test` 가 종료코드 0
3. 이미 결제된 건은 토스 개발자센터에서 취소하고 클로버를 되돌린다(5걸음과 같다)

## 자주 헷갈리는 것

- **재배포 안 하면 안 바뀐다.** 환경변수만 고치고 화면을 보면 옛 열쇠가 그대로다
- 화면 열쇠(`NEXT_PUBLIC_…`)는 공개돼도 되는 열쇠다. 시크릿 키(`TOSS_SECRET_KEY`)만 비밀. 시크릿 키가 어디든 찍혔으면 토스에서 즉시 재발급
- 결제 금액은 브라우저가 못 정한다. 상품 표(`packs.ts`)에 없는 금액은 서버가 「결제 금액이 맞지 않아요」 로 거절한다
- 클로버 유효기간은 1년(0921 개정, /refund 제4조). 라이브 첫 결제일부터 실제 고객에게 적용된다
