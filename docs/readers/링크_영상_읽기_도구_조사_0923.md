# 링크, 영상 읽어오는 도구 조사와 판정 (2026-09-23)

대표 지시: 「링크, 영상 읽어오는 MCP/CLI 깃허브에서 신뢰성 가장 높은 걸로 찾아서 붙여. 이거랑 연동성을 높여야 해.」

## 결론 한 줄
웹 글은 **@mozilla/readability + linkedom**, 유튜브는 **youtube-caption-extractor** 를 붙였다. 둘 다 우리 서버(Vercel, Node) 안에서만 돌고 자료가 밖으로 나가지 않는다. 읽기 함수는 `readUrl(url)` 하나로 모아 자료 넣기와 대화 중 링크 읽기가 같은 길을 쓴다.

## 판정 기준 4개
1. 우리 Vercel Node 서버리스에서 그대로 도는가 (바이너리 실행 불가, 60초 제한)
2. 최근 6개월 안에 손질되고 있는가
3. 자료가 외부 서버로 나가지 않는가 (팬 자료, 대표 자료가 남의 서버에 남으면 안 된다)
4. 한국어 페이지(네이버 블로그 액자, 브런치, 티스토리)가 되는가

### MCP 서버들 (mcp-server-fetch, mcp-youtube, @anthropic 계열)
전부 「클로드 데스크톱이 부르는 프로그램」이다. 우리 서버 안에서 봇이 부르는 건 라이브러리여야 한다. 그래서 MCP 는 붙이지 않고, MCP 서버들이 안에서 쓰는 라이브러리(readability, 자막 추출기)를 직접 붙였다.

## 붙인 자리
- `src/domains/os/readers/index.ts` **readUrl(url, 한도)**: 단일 입구. 안전 검사 → 유튜브면 자막 / 웹이면 본문 추출 → 글
- `src/domains/os/readers/article.ts`: readability + linkedom. 본문을 못 찾으면 옛 방식(태그만 걷어내기)으로 되돌아간다
- `src/domains/os/readers/youtube.ts`: 자막(한국어 우선, 없으면 자동 자막, 없으면 아무 자막) + 제목 + 채널(공식 oEmbed). 자막이 없으면 「이 영상은 자막이 없어요」를 글에 적고 제목과 설명만 저장
- `src/domains/agent/fetch-url.ts`: 「안전하게 가져오기」만 남김(SSRF 차단, 튕김 3회 재검사, 크기와 시간 한도, 네이버 액자 주소 변환). 글로 바꾸는 일은 readers 로 옮김
- 자료 넣기 `src/domains/os/knowledge.ts addLinkSource` 와 대화 중 링크 읽기 `src/app/api/chat/route.ts` 가 **같은 readUrl** 을 쓴다

## 알려진 한계 (지어내지 않고 이유를 돌려준다)
- 브런치는 일반 브라우저 흉내 이름(User-Agent)으로 열면 카카오 로그인으로 튕긴다. 우리 봇 이름(CuriAI-Bot)으로 열면 본문이 온다. 이름표를 바꾸지 마라
- 유튜브가 데이터센터 IP(Vercel)를 막을 때가 있다. 그때 자막은 빈 값이 오고 공식 oEmbed 제목은 대개 살아 있어 「제목과 설명만」으로 저장된다. 배포 후 실제 Vercel 에서 한 번 확인할 것
- 큐리어스 본체(curious-500.com)처럼 화면을 프로그램으로 그리는 쪽은 40자 정도만 나온다. 「읽을 글을 못 찾았어요」로 알린다
- 자막 언어는 한국어를 먼저 찾고, 없으면 첫 자막을 쓴다. 어느 언어를 골랐는지는 도구가 알려주지 않는다
