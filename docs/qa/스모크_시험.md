# 라이브 스모크 시험 — 배포가 깨졌는지 사람이 안 봐도 알기

작성 2026-09-23. 대상 = 라이브 https://www.curi-ai.com. **읽기만 한다.** 돈·발송·저장을 일으키지 않는다.
「스모크(연기) 시험」 = 불 났는지 연기만 보는 시험. 깊게 안 보고, 큰 화면 몇 개가 열리는지·핵심 버튼이 눌리는지만 본다.

## 1. 무엇을 보나 (시험 13개 + 선택 1개)

| 번호 | 보는 것 | 깨졌을 때 뜻 |
|---|---|---|
| 1 | `/` `/os/welcome` `/os?demo=1` 세 화면이 200 으로 열리고, **우리 코드** 콘솔 오류 0 (폰·데스크톱 각각) | 배포가 통째로 죽었거나, 화면 그리는 코드가 터진다 |
| 2 | `/os?demo=1` 에서 봇 타일 3개 → 첫 타일 클릭 → 대화 머리에 봇 이름 → 입력창 보임 → 글자 넣으면 캐릭터가 `listening`(듣는 얼굴) | 봇 팀 화면 흐름이 끊겼다(명단·대화·캐릭터 중 하나) |
| 3 | 폰(375px)에서 가로 스크롤 없음 | 폰에서 화면이 옆으로 삐져나간다 |
| 4 | `/manifest.json` 200 + `start_url`·`display`·아이콘 있음, `/sw.js` 200 | 홈 화면에 앱 설치가 안 된다 |
| 5 | `/api/os/team` 손님 응답이 정확히 `{team:[], guest:true}` | 로그인 판정이나 팀 API 가 바뀌었다 |
| 6 | 라이브 HTML·자바스크립트 번들 17개에 열쇠 흔적 없음: `live_ck_`(토스 실결제 키)·`sk_`(비밀 키 꼴)·서비스 롤 JWT → **실패**. `test_ck_`(토스 시험 키)는 참고로만 적음 | 열쇠가 공개 화면에 새고 있다. **즉시 폐기·재발급** |
| 선택 | `SMOKE_CHAT=1` 일 때만 `/api/chat` 1회: 200 + `x-llm-driver` 머리글 + 첫 `data:` 조각 30초 안 | 모델(솔라) 연결이 끊겼다 |

- 콘솔 오류는 **우리 서버 주소에서 난 것만** 센다. 광고·계측(PostHog·Clarity·GTM 등)·다른 회사 주소의 404 는 소음으로 걸러 「걸러낸 서드파티 메시지 N건」으로만 적는다.
- 대화 API 는 손님 하루 8회 한도가 있어 기본은 건너뛴다. 켜면 하루 1회만 쓴다.
- 브라우저에 나가는 Supabase `anon` JWT 는 원래 공개용이라 통과다. `service_role` 이면 실패.

## 2. 돌리는 법

```bash
npm ci                                 # 처음 한 번
npx playwright install chromium        # 처음 한 번 (브라우저 내려받기)
npx playwright test                    # 라이브 전체 (약 15초)
npx playwright test --project=phone    # 폰만
SMOKE_CHAT=1 npx playwright test       # 대화 API 도 1회 포함
SMOKE_BASE=https://미리보기주소 npx playwright test   # 다른 주소를 볼 때
npx playwright show-report             # 결과를 브라우저로 보기
```

- Vercel 이 main 을 **배포 완료**했을 때(깃허브 연동이 보내는 배포 성공 신호)
- 매일 **09:00 KST**
- 손으로: 저장소 → Actions → smoke → Run workflow (주소·대화 포함 여부 고를 수 있음)

슬랙 알림은 저장소 시크릿 `SLACK_WEBHOOK_URL` 이 있을 때만 나간다. 없으면 조용히 건너뛴다(빨간불은 Actions 탭에 남는다).

## 3. 실패했을 때 읽는 법

1. **어느 줄이 빨간가** = 위 표의 번호가 곧 어디가 깨졌는지다. 이름이 한국어라 그대로 읽으면 된다.
2. 실패 메시지 첫 줄에 이유를 한국어로 적어 두었다. 예: `봇 타일이 3개여야 한다` · `/os?demo=1 상태코드` · `열쇠 흔적: /charge: 토스 실결제 키(live_ck_) 노출`.
3. 스크린샷·흔적 파일 = 로컬은 `test-results/` 폴더, 깃허브는 실패한 실행의 **Artifacts** 에 `smoke-실패증거-…` 로 올라온다. 내려받아 `npx playwright show-trace 파일.zip` 하면 그 순간 화면을 한 장씩 되감아 볼 수 있다.
4. 한 번 실패하고 재시도에 통과했으면(깃허브는 1회 재시도) 네트워크 흔들림일 가능성이 크다. 같은 항목이 **두 번 연속** 빨갛면 진짜 고장으로 본다.
5. 열쇠 흔적(6번)이 빨갛면 코드 고치기 전에 **그 열쇠를 먼저 폐기·재발급**한다. 코드에서 지우는 것만으로는 안 된다(이미 노출됨).
