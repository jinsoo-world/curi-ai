# 연결 서비스 열쇠 발급표 (대표가 그대로 따라 하는 판)

작성 2026-09-30. 화면 = 큐리AI `/os/connect` 「서비스」 탭.

## 0. 먼저 알 것

- **누구 계정이 붙나** = 큐리AI 사용자 본인의 계정. 우리 회사 계정을 붙이는 게 아니다. 사용자가 「연결하기」를 누르면 그 서비스 로그인 화면으로 가서 「허용」을 누른다.
- **대표가 할 일** = 서비스마다 개발자 콘솔에서 「앱」 하나를 만들고, 거기서 나오는 열쇠 2개(아이디, 비밀)를 Vercel 환경변수에 넣는다. 열쇠가 없는 서비스는 화면에 「준비 중」으로 나오고 단추가 눌리지 않는다.
- **돌아오는 주소(리디렉트 URI)** 는 글자 하나까지 같아야 한다. 아래 표의 값을 콘솔에 그대로 붙인다. 시험용은 `http://localhost:3000` 으로 바꿔 하나 더 넣는다.
- 앱 이름은 전부 **큐리AI** 로 한다(콘솔이 영어만 받으면 `CuriAI`).
- 공통 자물쇠 `CONNECTOR_SECRET_KEY` 가 먼저 있어야 한다. 32바이트 무작위 값(base64 또는 hex). 없으면 14개 전부 「준비 중」.
  - 2026-09-28 Vercel Production 에 처음 넣었다(값은 Vercel 에만 있다). 그 전에는 없었다.
  - ⚠️ 한 번 넣은 뒤에는 바꾸지 않는다. 바꾸면 이미 잠가 둔 연결 토큰(`connectors.secret_encrypted`)과 정산 계좌(`creator_payout_profiles.account_number_encrypted`)를 풀 수 없게 된다.
- 우리 쪽 돌아오는 주소는 `NEXT_PUBLIC_APP_URL` 로 만든다. Production 값은 `https://www.curi-ai.com` (2026-09-28 에 옛 `app-seven-delta-90.vercel.app` 에서 바꿨다). 콘솔에 넣는 주소도 전부 `https://www.curi-ai.com/api/connect/<서비스>/callback` 이다.

열쇠를 미리 넣어 두는 것은 괜찮다(구글 드라이브와 지메일은 같은 구글 열쇠를 쓴다). 봇이 쓰지 않는 서비스는 열쇠가 있어도 열리지 않는다.

## 2. 넣는 곳

Vercel → 프로젝트 → Settings → Environment Variables. Production 에 넣고 다시 배포하면 그 서비스의 「준비 중」 배지가 사라지고 「연결하기」가 눌린다. (⛔ 도구 규칙이 Vercel 환경변수 쓰기를 막아서 이건 대표 손이다.)

## 3. 심사·시간

| 서비스 | 심사 | 걸리는 시간 |
|---|---|---|
| 노션 공개 통합 | 있음(간단) | 발급 즉시 시험 가능, 다른 사용자가 붙이려면 심사 1~3일 |
| 구글 4종 | 있음. 시험 사용자 100명까지는 심사 없이 됨 | 즉시(시험 사용자). 공개는 앱 인증 2~6주 |
| 메타 2종(스레드, 인스타) | 있음. 개발 모드에서는 역할 등록한 계정만 | 즉시(개발 모드). 공개는 앱 리뷰 1~4주 |
| 카카오, 네이버, Zoom, 깃허브, 슬랙 | 없음(카카오·네이버는 검수 없이도 본인 계정은 됨) | 즉시 |

## 4. 어디에 무엇이 저장되나

- 토큰 JSON 은 `connectors.secret_encrypted` 에 **잠겨서**(AES-256-GCM) 들어간다. 화면과 응답에는 계정 힌트(`jin@…`)만 나간다.
- 연결 해제 = 그 줄을 지운다. 서비스 쪽 「앱 연결 끊기」는 사용자가 그 서비스 설정에서 따로 할 수 있다.
