# 큐리어스 계정 연결 명세 (curious-500.com 쪽에 필요한 창구)

작성 2026-09-28. 받는 사람 = 큐리어스 개발봇(curious-500.com 담당). 큐리AI 쪽 코드는 이미 이 명세대로 들어가 있다.

## 0. 왜 새 창구가 필요한가

- 목표: 큐리AI 사용자가 **본인** 큐리어스 계정을 한 번 연결하면, 큐리AI 봇이 그 사람의 어울림, 신청자 수, 커뮤니티 글을 **읽기만** 한다.
- 지금 본체에 있는 것: `https://curious-500.com/api/v2/*` 는 로그인 쿠키 `access_token` 을 Bearer 로 받는다. 토큰을 발급하는 창구(OAuth, 개인 토큰 페이지)는 없다(`/oauth/authorize`, `/api/v2/oauth/*`, `/.well-known/openid-configuration` 모두 404, 2026-09-28 확인).
- 큐리어스 CLI(`~/dev/curious-cli`)는 사용자가 브라우저 주소창에 `javascript:` 를 넣어 `access_token` 쿠키를 복사해 붙이는 방식이다. 이 방식을 큐리AI 에서 쓰지 않는 이유:
  1. 그 토큰은 **그 사람 계정 전체 권한**(결제, 개설, 공개 전환 포함)이다. 읽기만 하려는 큐리AI 가 들고 있을 이유가 없다.
  2. 4060 사용자에게 「주소창에 코드를 붙여 넣으라」는 안내는 피싱 수법과 똑같다.
  3. 만료, 갱신, 연결 끊기(철회)가 없다.

## 1. 흐름 (OAuth 2.0 Authorization Code + PKCE)

```
큐리AI /os/connect 「큐리어스 연결하기」
  → GET https://curious-500.com/oauth/authorize?...           (본체: 로그인 + 동의 화면)
  → 302 https://www.curi-ai.com/api/connect/curious/callback?code=...&state=...
  → 큐리AI 서버가 POST https://curious-500.com/api/v2/oauth/token (code → 토큰)
  → 큐리AI 가 토큰을 AES-256-GCM 으로 잠가 저장, 봇이 partner API 를 읽기만 한다
```

## 2. 필요한 창구 (주소는 글자 하나까지 이대로. 큐리AI 코드에 박혀 있다)

### 2-1. `GET https://curious-500.com/oauth/authorize` (화면)

| 쿼리 | 값 |
|---|---|
| `response_type` | `code` 만 |
| `client_id` | 큐리AI 에 발급한 아이디 |
| `redirect_uri` | 등록된 값과 **완전 일치**만 허용: `https://www.curi-ai.com/api/connect/curious/callback`, `http://localhost:3000/api/connect/curious/callback` |
| `scope` | 띄어쓰기로 이은 목록. 큐리AI 는 `profile:read studies:read members:read posts:read` 를 보낸다 |
| `state` | 그대로 돌려준다 |
| `code_challenge`, `code_challenge_method` | `S256` 필수 |

- 로그인 안 돼 있으면 본체 로그인(카카오 등) 뒤 이 화면으로 돌아온다.
- 동의 화면 문구(제안): 「큐리AI 가 내 큐리어스에서 이것을 **읽어요**: 내 프로필 이름, 내가 연 어울림과 참여한 어울림, 내 어울림 신청자 별명과 수, 내가 쓴 글. 결제, 정산, 개설, 공개, 글쓰기는 못 해요.」 [허용] [취소]
- 허용 → `302 {redirect_uri}?code={code}&state={state}`. code 는 한 번만, 10분 안에만 쓸 수 있다.
- 취소 → `302 {redirect_uri}?error=access_denied&state={state}`.

### 2-2. `POST https://curious-500.com/api/v2/oauth/token`

`Content-Type: application/x-www-form-urlencoded`, 클라이언트 인증은 **본문**(`client_id`, `client_secret`).

| grant_type | 추가 칸 |
|---|---|
| `authorization_code` | `code`, `redirect_uri`(authorize 때와 같은 값), `code_verifier` |
| `refresh_token` | `refresh_token` |

성공 `200`:
```json
{ "access_token": "…", "token_type": "Bearer", "expires_in": 3600, "refresh_token": "…", "scope": "profile:read studies:read members:read posts:read" }
```
- access_token 1시간, refresh_token 30일, **돌려 쓰기(rotation)**: refresh 할 때마다 새 refresh_token 을 주고 옛 것은 죽인다.
- 실패 `400 { "error": "invalid_grant" | "invalid_client" | "invalid_request" }`. 200 에 error 를 섞지 않는다.

### 2-3. `POST https://curious-500.com/api/v2/oauth/revoke` (있으면 좋음)

본문 `token`, `client_id`, `client_secret`. 사용자가 큐리AI 에서 「해제」하면 부른다. 본체 설정 화면에도 「연결된 앱: 큐리AI [연결 끊기]」가 있으면 좋다.

### 2-4. 읽기 전용 partner API (`https://curious-500.com/api/v2/partner/*`)

공통 규칙
- `Authorization: Bearer {access_token}` 만 받는다(쿠키 세션 토큰은 받지 않는다. partner 토큰은 이 주소들 밖에서 받지 않는다).
- **전부 GET.** 토큰 주인 본인 것만. 스코프가 없으면 `403 { "error": "insufficient_scope" }`, 토큰이 죽었으면 `401 { "error": "invalid_token" }`(큐리AI 는 401 에서만 refresh 를 한다).
- 응답에 **전화번호, 이메일(본인 /me 제외), 결제, 정산, 매출 칸을 넣지 않는다.**
- 목록은 `{ "items": [...], "nextCursor": "…" | null }`, `limit` 최대 50, `cursor` 로 다음 쪽.
- 분당 60회 정도 제한, 넘으면 `429`.

| 주소 | 스코프 | 쿼리 | 응답 |
|---|---|---|---|
| `GET /api/v2/partner/me` | `profile:read` | 없음 | `{ "id": 123, "nickname": "열정진", "isLeader": true }` |
| `GET /api/v2/partner/studies` | `studies:read` | `role=leader\|member\|all`, `limit`, `cursor` | `items[]`: `{ "id": 7, "title": "…", "role": "leader"\|"member", "visibility": "DRAFT"\|"PRIVATE"\|"PUBLIC"\|"CLOSED", "price": 0, "capacity": 100, "applicantCount": 42, "nextSessionAt": "2026-10-14T20:00:00+09:00" \| null, "url": "https://curious-500.com/…" }` (최근 순) |
| `GET /api/v2/partner/studies/{id}/members` | `members:read` | `limit`, `cursor` | 토큰 주인이 **그 어울림의 리더일 때만**. `{ "total": 42, "items": [{ "nickname": "봄날", "joinedAt": "2026-09-01T10:00:00+09:00" }] }`. 리더가 아니면 `403` |
| `GET /api/v2/partner/posts` | `posts:read` | `scope=mine` 또는 `scope=study:{id}`(내가 리더이거나 참여한 어울림만), `limit`, `cursor` | `items[]`: `{ "id": 1, "studyId": 7 \| null, "title": "…", "excerpt": "본문 앞 500자", "createdAt": "…", "commentCount": 3, "url": "…" }` |

## 3. 발급해서 큐리AI 에 줄 것

- 큐리AI 용 confidential client 1개: `client_id`, `client_secret`.
- 등록 redirect URI 2개(위 2-1).
- 대표가 Vercel Production 에 `CURIOUS_OAUTH_CLIENT_ID`, `CURIOUS_OAUTH_CLIENT_SECRET` 을 넣고 다시 배포하면 /os/connect 의 큐리어스 카드가 「곧 열려요」에서 빠져 「연결하기」가 된다. 큐리AI 쪽 추가 코드는 없다.
